# RC.7 — nawigacja, onboarding i Twitch
Układ tymczasowy: istniejące grupy jako punkt wyjścia. Ustawienia > Ukryj zakładki; koło zębate i Ctrl+, zawsze dostępne. Edytuj menu: przeciągaj kategorie i zakładki, upuszczaj na nagłówkach lub między elementami; maks. 2 poziomy kategorii, 45 węzłów, wszystkie strony zachowane dokładnie raz. Zwijanie i nazwy zapisane w layout.v1. Usuń kategorię promuje jej zawartość. Stary układ migruje do domyślnego ukrytego inspektora. Eksport pozostaje, import CSV/JSON usunięty z UI, dane historyczne zachowane. Migracja PSSA 1.x tylko na dole Integracji. OBS WebSocket przemianowany, zaawansowane funkcje zwinięte.
## Logowanie
Użytkownik zarejestrował aplikację PSSA i przekazał publiczny Client ID. Identyfikator jest domyślną wartością w electron.vite.config.ts; opcjonalnie można nadpisać go zmienną build PSSA_TWITCH_CLIENT_ID (GitHub Actions Variables). Nie tworzyć ani nie wklejać Client Secret. Build wstrzykuje jedynie publiczny identyfikator do main. Bez niego uproszczone logowanie nieaktywne; własny Client ID/Secret w zaawansowanych jako kompatybilność. Device Code Grant: otwiera tylko oficjalny https://www.twitch.tv/activate, wyświetla kod, odpytywanie zgodnie z interval/slow_down, anulowanie przez AbortController, tokeny w DPAPI, odświeżanie bez secret. Istniejące sesje pozostają działające. Publiczne refresh tokeny są rotowane i mogą wygasnąć; ponowne logowanie wymagane. Dokumentacja https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/ . Testy mock i smoke obecności publicznego ID w buildzie; rzeczywista autoryzacja wymaga zalogowania przez użytkownika. Przycisk powitalny rozpoczyna autoryzację bezpośrednio, gdy stan integracji jest dostępny.
