# Tryby pracy i aktualizacje
## Tryby
Studio: dotychczasowy polling UI 1.5–2s. Streaming: polling UI 5s, ograniczone przejścia CSS. Gdy dokument ukryty, UI pomija odczyty. Background: po jawnej akceptacji przejścia do tła BrowserWindow jest ukrywany i ładuje about:blank (odmontowanie React oraz jego timerów); proces Chromium nie jest gwarantowanie usuwany. Backend, EventSub, kolejka, OBS, Agent i zapis próbek działają bez zmian. Powrót z zasobnika lub drugiego uruchomienia PSSA w trybie Streaming. Zamknięcie aplikacji przez X/zakończ kończy silnik. Niezapisane szkice przepadają po wyładowaniu renderera — UI ostrzega. Nie są to pomiary oszczędności CPU/RAM/GPU; rzeczywiste pomiary pozostają otwarte.
## Backup i restore
Pojedynczy plik .pssabackup (SQLite, format v1, schema 4), jawne wybrane tabele i ustawienia, pliki mediów jako BLOB zweryfikowane przez SHA-256. Nie kopiuje tokenów, haseł, kluczy Agenta/overlay, logów, plików runtime Electron. Zawiera historię, pseudonimy i sól czatu, treści alertów; nie udostępniać publicznie. Limit 1 GB, 50 MB/plik, 10000 plików; brakujące media nie są odtwarzane z niczego. Uszkodzone pliki blokują backup. Wybór nowej ścieżki poza katalogiem danych. Operacja synchroniczna, poza wykrytą transmisją/nagrywaniem (brak połączenia nie dowodzi, że OBS nie nadaje). Przy dużych bazach może czasowo blokować UI; profilowanie w audycie C.
Restore: wybór i potwierdzenie, walidacja i staging prywatnej kopii. Po restarcie przed startem usług: kopia bezpieczeństwa before-restore, weryfikacja danych przez kopiowanie do znanego schematu, dodanie brakujących mediów, transakcyjna wymiana tabel i ustawień. Lokalna autoryzacja i adres overlay pozostają; oczekujące/odtwarzane alerty przechodzą do skipped. Nie kasujemy dodatkowych mediów. Awaria może pozostawić dodatkowe pliki, nie powinna zmienić danych SQLite. Odrzucony plik zostaje zachowany. Backup nie jest zaszyfrowany; przechowywać prywatnie. Przywracanie tylko zgodnego schematu, nie dowolnego pliku SQLite.
## Onboarding i diagnostyka
Pierwsze uruchomienie: dobrowolny import starego PSSA lub historii CSV/JSON, przejście do integracji albo start lokalny. Nie ma bezpośredniego SullyGnome. Raport JSON: wersje runtime, stan integracji, liczba procesów, suma working set, chwilowy CPU, DB/WAL, kolejka, ostatni restore i uptime. Bez nazw kont, ścieżek, sekretów i surowych logów. Agent jako osobny proces nie jest ujęty w sumie metryk.
## Aktualizacje i instalator
Wybór stable/beta, jawne sprawdzenie lub opcjonalny odczyt GitHub Releases co 6h. Walidacja semver i stały adres repozytorium, bez auto-download i uruchamiania niepodpisanych exe. Automatyczna instalacja wymaga podpisywania i zweryfikowanego kanału wydawniczego; nie publikujemy release bez akceptacji. Beta 2.0.0-beta.1 zachowuje AppId i katalog PSSA 2 Dev dla ciągłości danych oraz izolacji od Python. NSIS per-user, skróty, dane przy odinstalowaniu nie są usuwane. CI rozszerzone o cichą instalację w świeżej ścieżce i uruchomienie zainstalowanego exe, oprócz build i packaged smoke. Upgrade istniejącej instalacji i uninstall pozostają do testu.
