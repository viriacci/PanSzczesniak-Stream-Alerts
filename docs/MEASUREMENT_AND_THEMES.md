# Skórki, pomiar i crash logi — RC.3
Baza RC.2 commit afe100b3, CI 45380348076 (83/83 testów i pełna instalacja).
## Skórki
Ustawienia > Skórki aplikacji. PSSA Black & Gold, ViviOnyx Onyx Atelier (śliwka/lawenda), Shiroe Glacial Archive (grafit/błękit). Dwie dodatkowe palety są koncepcjami, NIE zweryfikowanym brandingiem twórców. Vivi: publiczne tytuły streamów z motywami grzybów i nietoperzy https://www.twitchmetrics.net/c/683698584-vivionyx; Shiroe: shiroe_com. Brak potwierdzonych HEX/logotypów; żadnych zewnętrznych obrazów. Skórki zmieniają wyłącznie lokalny interfejs, nie alerty/overlay ani konto. Zapis w runtime.v1, stare ustawienia domyślnie pssa, kopia ustawień obejmuje skórkę. CSS bez nowych zależności i animacji tła.
## Rzeczywisty pomiar
Diagnostyka > Narzędzia zaawansowane > Pomiar wydajności. Domyślnie zwinięty i wyłączony; potwierdzenie natywne. Nie symuluje zdarzeń. Co 10 s: CPU systemu z os.cpus (delta idle/total), RAM systemu total-free, CPU PSSA z cumulativeCPUUsage i PID+creationTime, RAM working set, procesy, eventLoopUtilization i opóźnienie timera, stan integracji, kolejka i liczniki zakończeń/niepowodzeń/suppressed/retry, ostatnia świeża telemetria OBS (CPU/RAM/FPS/skipped counters/streaming/recording), Agent CPU/RSS po istniejącym heartbeat tylko w trakcie sesji. CPU aplikacji i Agenta jako procent wszystkich logicznych rdzeni, przedział ze zniknięciem procesu oznaczony brakiem danych. PSSA CPU nie obejmuje oddzielnego OBS i Agenta. Sumaryczny working set może liczyć pamięć współdzieloną wielokrotnie. OBS wartości z API, FPS OBS nie FPS gry. Nie ma automatycznego przypisania wpływu PSSA na FPS gry.
Opcjonalne GPU: Windows WMI/CIM GPU engine counters, co 60 s, agregacja wykorzystania silnika per adapter/engine i największa wartość; nie VRAM ani GPU przypisane PSSA. Brak licznika/timeout oznacza brak danych, a nie 0. Proces PowerShell ma limit 8 s i jest zabijany przy zakończeniu sesji; własny koszt wchodzi do CPU systemu. GPU wyłączone domyślnie. Nie uruchamiać żadnych poleceń z tekstu użytkownika.
Sesja zapisywana jako NDJSON w measurements, próbka od razu do pliku; brak end po awarii = interrupted. Maks. 24 h/8640 próbek, 100 sesji; ręczne archiwizowanie. Brak timerów pomiaru poza sesją. Sesja pozostaje aktywna bez okna Background, kończy się przy całkowitym zamknięciu PSSA. Raporty średnia/P95/max/N, porównanie wybranych sesji i wersji, CSV/JSON z wszystkimi próbkami. Średnia CPU systemu/PSSA i ELU ważona czasem przedziału; inne metryki średnia arytmetyczna ważnych próbek; brak danych null, GPU dedup po timestampie. Test rzeczywistego streama jeszcze niewykonany.
Raport pokazuje także CPU/RAM OBS, opóźnienie timera, szczyt kolejki i przyrost liczników skipped frames w ciągłych przedziałach bez resetu. CI uruchamia rzeczywisty krótki pomiar, niszczy/odtwarza okno i sprawdza zachowanie raportu.
## Crash logi
crashes.jsonl/agent-crashes.jsonl (+ .previous, rotacja 1 MB), czas, wersja, proces, typ, reason, exitCode, ograniczone ramki stosu basename:line:column. Bez tekstu wyjątku, tokenów, pełnych ścieżek, nazw kanału, treści czatu. Main uncaughtExceptionMonitor, unhandled rejection (kontrolowane zakończenie), startup failure, render/child gone, renderer JS/React z ograniczeniem częstotliwości, Agent start/uncaught. Electron CrashReporter uploadToServer:false, lokalne crash-dumps/; native dump może zawierać prywatną pamięć, nie dołączać do zwykłego eksportu. Eksport JSON z dotychczasową diagnostyką i ostatnimi 100 błędami, ręczny. Nie automatycznie wysyłamy raportów. Brak zrzutów przy niektórych wymuszonych zakończeniach/system power loss; niepełny raport pomiaru pozostaje.

Build generuje ukryte source mapy w osobnym artefakcie CI pssa-debug-source-maps; wykluczone z instalatora. Zachować mapy dokładnego commita, aby rozwiązywać ramki JS do źródeł TS. Smoke sprawdza redakcję przykładowego błędu renderera. Native crash dump nie jest automatycznie eksportowany.
